LifeOS · Ad Ops Platform · Connected Accounts 系列 02 ✓ 內部階段可直接照做

Meta System User 接入設計

這份是給「內部使用」階段的實作 runbook——目標是讓 ConnectedAccount 拿到一個 綁在 Business，不綁任何一個人的 Meta token。因為只接自己公司底下的廣告帳戶， 這條路不需要 App Review，可以直接動手做。

§01

為什麼內部階段這麼簡單

Meta 的 App Review（審核那個要交 demo 影片、等好幾週的流程）只有在你的 App 要存取「不屬於你 自己 Business Manager」的廣告帳戶時才會被要求。只要今天串的帳戶都在自己公司的 Business Manager 底下，App 留在 Development 模式就能拿到完整權限——這就是為什麼「先做 Meta」是對的順序： 內部階段幾乎零阻力，之後要轉外部時，權限跟資料模型都已經是對的形狀，只差申請審核。

前提：你要有這個 Business Manager 的 Admin 權限，而且要接的廣告帳戶已經在裡面。 如果還沒有 Business Manager，先去 business.facebook.com 建一個。
§02

建立 Meta App（如果還沒有）

  1. 1developers.facebook.com → My Apps → Create App類型選 Business，關聯到剛剛那個 Business Manager。
  2. 2加上 Marketing API 這個 ProductApp Dashboard → Add Product → Marketing API → Set Up。
  3. 3記下 App ID 跟 App Secret之後產生 / 驗證 token 都會用到，存進我們自己的環境變數，不要進 git。
§03

建立 System User 並發 token

  1. 1Business Settings → Users → System Users → Add命名清楚，例如 ad-ops-platform-sync，角色選 Admin（要指派帳戶權限需要）。
  2. 2Assign Assets → Ad Accounts勾選要同步的廣告帳戶，權限給 Manage campaigns。之後每加一個新帳戶，回這裡加勾選就好，不用重新走一次登入。
  3. 3Generate New Token選剛剛建的 App，勾選下面的權限（scopes），按下去 token 只會顯示一次——當場存進我們系統的 ConnectedAccount.accessToken（加密）。

要勾的權限

ads_management

讀寫廣告活動、群組、關鍵字——AI 生成關鍵字/Sitelinks 之後要靠這個寫回去。

ads_read

讀成效數據，Performance 頁的曝光/點擊/花費同步靠這個。

business_management

管理 Business 底下的資產（含之後外部階段要用到的 Partner 指派）。

read_insights

Insights API，ROI 頁要拿轉換數據會用到。

§04

Token 怎麼存、怎麼過期

System User token 是否「永久不過期」取決於 Business Verification 有沒有完成。內部階段 沒完成也能用（token 效期較長但非永久），建議直接把 Business Verification 一併做掉——反正外部階段一定 需要，早做早好，不用之後回頭重弄一次連線。

ConnectedAccount 欄位這裡怎麼填
platformmeta
platformAccountId廣告帳戶 ID，格式 act_<數字>
authMethodsystem_user
accessToken§03 產生的 System User token（加密存放）
tokenExpiresAtBusiness 已驗證 → null；未驗證 → 記下 Meta 回傳的效期
status預設 connected，token 打 API 回 190 錯誤代碼時轉 needs_reauth
§05

同步邏輯實際打的 API

三個端點就能餵飽現有頁面（Performance／Keyword Quality 對應的活動結構／ROI）：

GET /{ad_account_id}/campaigns
    ?fields=id,name,status,objective
    &access_token={system_user_token}

GET /{ad_account_id}/insights
    ?fields=campaign_name,impressions,clicks,spend,ctr,cpc
    &time_range={"since":"2026-08-01","until":"2026-08-14"}
    &level=campaign
    &access_token={system_user_token}

GET /debug_token
    ?input_token={system_user_token}
    &access_token={app_id}|{app_secret}   # 定期呼叫，確認 token 還活著
Rate limit 提醒：Meta 用 Business Use Case Usage 計算額度，回應 header 裡的 x-business-use-case-usage 會告訴你還剩多少——同步排程要抓這個做 backoff，不要固定 每 N 分鐘硬打。
§06

外部階段才要處理的事（現在不用做）

這段是為了讓你知道「以後要加什麼」，不是現在的待辦。轉外部後，客戶端不會有登入畫面——他們是在 自己的 Business Manager 裡把我們的 Business 加成 Partner（Business Settings → Ad Accounts → Assign Partner，貼我們的 Business ID），或是直接把我們的 System User 加進他們的資產權限。 整個過程完全不經過任何人的 Facebook 個人登入——這就是从根本解決「帳戶連來連去找不到」的方式，而且 Meta 官方就是設計成這樣給 agency 用的。

要打開這條路，需要：App Review（ads_management / ads_read 升級到 Advanced Access，交使用情境說明跟 demo）、Business Verification（§04 提到的，屆時是必要 而非建議）、以及 ConnectedAccount 多開一個 organizationId 對應到不同客戶。資料模型現在就是 對的形狀，屆時不用重寫。
